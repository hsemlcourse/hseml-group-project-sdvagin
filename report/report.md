## 1. Введение и постановка задачи

* **Цель проекта:** Предсказать, согласится ли клиент открыть срочный банковский депозит по итогам общения с оператором. Практическая ценность: возможность звонить только самым перспективным клиентам, экономя время колл-центра, деньги банка и не раздражая лояльную аудиторию спамом.
* **Формулировка задачи:** Бинарная классификация. Целевая переменная: `1` открыл вклад, `0` отказался.
* **Обоснование метрики:** В данных огромный дисбаланс (89% отказов против 11% согласий). Метрика Accuracy бесполезна (константная модель выдаст 89%). Ключевой выбрана **F1-score**, так как она ищет баланс. В качестве вспомогательной метрики для оценки разделяющей способности используется **ROC-AUC**.

---

## 2. Поиск и описание данных

* **Источник данных:** Классический Bank Marketing Dataset из репозитория UCI. Выбран, так как содержит реальные логи маркетинговых кампаний банка с богатым набором макроэкономических показателей.
* **Описание датасета:**
* *Объём:* 41 188 строк и 21 столбец.
* *Признаки:* Демография (возраст, работа, образование, статус), детали текущего звонка (длительность, месяц), история прошлых контактов и макроэкономика (индексы потребительских цен, ставка Euribor).



---

## 3. Обработка и подготовка данных

* **Полная очистка:**
* *Пропуски:* Явных `NaN` нет. Значения `unknown` в категориальных фичах оставлены как отдельная категория.
* *Дубликаты:* Обнаружены и удалены полные дубликаты строк.
* *Выбросы:* Обрезаны экстремальные значения по возрасту с помощью межквартильного размаха.
* *Типы данных:* Таргет переведен в строгий `int` (1/0).


* **Работа с фичами:**
* *Исходно:* 20 признаков.
* *Feature Engineering:* Созданы фичи `age_group` (категоризация возраста) и `contacted_before` (бинарный флаг наличия прошлых контактов).
* *Кодирование:* Применен One-Hot Encoding (`drop_first=True`) для текстовых колонок. Итоговое пространство раздулось до **53 фичей**.


* **Сплит данных:**
* Классическое разбиение 80/20 с жесткой стратификацией (`stratify=y`) для сохранения пропорций дисбаланса.
* *Защита от утечек:* StandardScaler обучался (`fit`) исключительно на тренировочной выборке.



---

## 4. Baseline-модель

* **Модель:** Логистическая регрессия (Logistic Regression).
* **Особенности:** Включен параметр `class_weight='balanced'` для штрафа за ошибки на редком классе.
* **Результаты (Test):** ROC-AUC = 0.9403, F1-Score = 0.6013.
* **Цель:** Оценить, насколько хорошо работают простые линейные зависимости, чтобы иметь точку отсчета.

## 6. Финальная модель и интерпретируемость

* **Выбор:** LightGBM с подобранными гиперпараметрами и кастомным порогом предсказания (0.7197). Модель дала максимальный прирост метрики F1 при сохранении высочайшего ROC-AUC.
* **Интерпретируемость (Feature Importance):**
1. `duration` (длительность звонка): Безоговорочно самый важный признак. Долгий и осмысленный диалог — главный триггер согласия.
2. `euribor3m` (ставка Euribor): При высоких банковских ставках клиенты охотнее фиксируют доходность и открывают вклады.
3. `pdays` (дней с прошлого контакта): Если клиент недавно и успешно общался с банком, шанс на повторную конверсию резко возрастает.

## 7. Деплой

* **Интерфейс:** Автоматически сгенерированный Swagger UI для тестирования эндпоинтов через браузер.
* **API:** Микросервис написан на **FastAPI**. Модель и скейлер загружаются в память при старте через `joblib`.
* Эндпоинт `POST /predict` принимает JSON с массивом из 53 фичей.
* Внутри происходит масштабирование, предикт вероятности, применение порога 0.7197 и возврат результата в текстовом виде.
* Сервер запущен локально и проброшен в сеть через `localtunnel`.

## 8. Заключение и выводы

* **Итоги:** Задача решена успешно. Разработана ML-модель, которая надежно выявляет склонных к депозиту клиентов, обойдя базовое решение по ключевой метрике F1-score более чем на 5%. Полностью настроен процесс деплоя в виде API.
* **Ограничения:** Главный предиктор (`duration`) неизвестен до совершения звонка. На текущий момент модель идеально работает только как онлайн-ассистент оператора во время разговора. Для оффлайн-скоринга базы до начала обзвона модель нужно переобучать без этой фичи.
* **Улучшения:** В будущем можно отказаться от One-Hot Encoding в пользу Target Encoding, чтобы не раздувать матрицу признаков, а также попробовать сгенерировать синтетические примеры меньшинства с помощью SMOTE.
